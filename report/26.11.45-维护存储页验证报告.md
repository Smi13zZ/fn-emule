## 一、做了什么

设置里新增「维护 / 存储」页，把面板各目录的实际磁盘占用列清楚，并提供清理入口。

| 项目 | 说明 |
| --- | --- |
| 更新包缓存 `updates/` | 清理时只保留最近 2 个，当前运行版本永不删除 |
| 配置备份 `backups/` | 只统计 |
| 删除任务保留的数据 `deleted/` | 只统计 |
| 统计历史 `history/` | 只统计 |
| 引擎日志 `amuled.log` / `.1` | 可清空 |
| 面板日志 `panel.log` / `.1` | 可清空 |
| 更新安装日志 `update-install.log` | 只统计 |

三项清理动作：**清理旧安装包**、**清空日志**、**全部清理**。前两者各带确认框，
框里写明预计回收多少，数字已扣除受保护的当前版本包。

## 二、两个关键设计决定

### 1. 引擎运行中必须 truncate，不能 unlink

aMule 用 `open("ab")` 拿到的 fd 一直指着旧 inode。如果直接 `os.remove`，目录项虽然没了，
磁盘空间却被那个 fd 继续占着——用户看到的就是「清了但没变小」。
所以引擎日志在运行中走 `open(path, "wb")` 就地把文件截成 0 字节，同一个 inode 继续被写，
空间立刻回收，正在进行的下载完全不受影响。

实测：造 68,818 字节日志 → 清理 → `amuled.log` 变 0 字节，引擎保持运行。

### 2. 当前版本的安装包永不删除

真要回滚时，本地那份当前版本的包就是最可能需要的东西。所以 `purge_updates()` 带一个
`protect_version`，文件名里含运行版本号的一律保留，不计入 `keep` 名额。

实测：目录里放 1 个 `26.11.44`（当前版本）+ 4 个旧包 + 1 个 `.part`，执行 `keep=1`：

```
removed: 26.11.8 / 26.11.5 / 26.11.20-fnos-all.fpk.part
kept:    fn-emule-26.11.44-fnos-all.fpk
protect: 26.11.44
```

## 四、「清屏」按钮也一并修了

日志页那个红色按钮以前只清浏览器内存里的数组：

```js
clearLogs: function () {
  this.logs = [];          // 只清浏览器内存
  this.logCleared = true;
  this.ok("logs.cleared");
}
```

刷新一下原样回来，用户点几次都以为坏了。现在它会真的清磁盘上的日志文件，
带确认框，清完重新拉列表并提示回收了多少。按钮文案也从「清屏」改成了「清空日志」。

## 六、安全约束

- `realpath` 校验：只删 `updates/` 目录内的文件，拒绝任何 `../` 逃逸
- `.part` 一律删除（升级脚本只认 `.fpk`），但**更新正在下载时整体拒绝清理**（409），
  避免下载线程写到已删除的文件上
- 引擎日志清理失败只降级成一条 warn，不影响其他步骤；部分失败时仍返回已成功的部分
- 文件名匹配只看扩展名与目录归属，不解析用户输入
