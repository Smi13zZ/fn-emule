## 本次改动

一键更新从「下载完交给系统、之后什么都看不到」改成全程可见、失败能说清原因、
装不上能自己退回来的流程。

### 后端

- 任务状态改为 `idle | checking | downloading | installing | failed`，附带
  `code`（语言中立）与 `detail`（中文回退文本）两路下发；成功路径两者都为空，
  阶段文案由界面按当前语言自拼。
- 新增 `attempt` 编号：每次发起 +1。失败状态不会自己回 idle，界面靠编号跳过
  「上一轮的死信」。
- `busy` 判定包含 `checking`，连点两次不会起两个下载。
- `POST /api/update/install` 接受界面已查到的 `{version,name,url}`，免掉一次
  没有进度的网络往返；没给才回查，且回查阶段显示「检查中…」。
- 下载长度对账：服务器给了 Content-Length 就必须收满，中断时按网络错误报出，
  不再把半截文件原子改名成「完整安装包」。
- 回滚：安装前把当前运行版本的包复制成 `updates/rollback.fpk`；查找目录把
  `updates/` 放第一位（一键更新每次都下载到这里），取最新一份并排除本次刚下的。
- 升级脚本重写：stop → uninstall → install-fpk → 轮询 status（起不来才 start）
  → 失败则用 `rollback.fpk` 装回。没有回滚包时只记一行日志，界面据此改文案。
- `netutil`：`FetchError` 带 code，新增 `error_code()` 递归拆 URLError 的壳；
  区分「连接被对端关闭」与「写入文件失败」，后者才提磁盘。
- `store`：`rollback.fpk` 单独豁免清理、不占保留名额。

### 前端

- 遮罩按阶段显示文案；下载阶段保留进度条 + 已下载/总量 + 百分比，进入安装后
  切「准备中…」，不假装还有百分比。
- 全局失败条：从任意页面发起更新失败都能看到，带「查看详情」与单独关闭。
- 失败原因按 code 翻译，英文界面零中文。
- 成功帧不再写 100/100（会渲染成「100 B / 100 B」），保持真实总量。
- 设置页底部提示按有没有回滚包切换文案。

### 清理

- 删除 74 组无引用的中英文案、3 条样式规则（`.grow` / `.spin` / `.topbar-server`）
  与 1 个颜色变量（`--hover`）。
- `updates_list` 里只写不读的 `rollback` 字段改由 `is_rollback_name()` 承担。
- 审计带变异自检 + 反向自检；i18n 601 处「中英不一致」是通用规则误报
  （本项目是扁平双表，非英文键名反查），已用针对性规则重跑，结论为 0 死键。
